Word documents, PowerPoint decks, Excel workbooks, EPUB books, and HTML pages are all parsed natively in Rust — zip/XML for Office Open XML formats, the calamine library for spreadsheets, and html5ever for HTML. No LibreOffice, no COM automation, no cloud conversion service. The same binary that runs on your laptop runs in your CI pipeline or inside a Docker container with no additional dependencies.

## Word (.docx)

anymd extracts every semantic element from a DOCX file: **headings**, **bold and italic**, **hyperlinks**, **nested lists**, **tables with merged cells**, **footnotes**, and **equations rendered as LaTeX**. Pictures are [exported as image files](#embedded-images) and marked in place.

### Tracked changes and comments

Tracked changes and comments are preserved as [CriticMarkup](https://github.com/CriticMarkup/CriticMarkup-toolkit) inline in the body, tables, text boxes, and footnotes. Every change carries the author's name and timestamp as a CriticMarkup comment immediately after the change:

| In Word | In the Markdown |
|---|---|
| Inserted text, or moved text at its new place | `{++new++}{>>Ana Lima (2026-09-29T14:05:00Z)<<}` |
| Deleted text, or moved text at its old place | `{--old--}{>>Ana Lima (2026-09-29T14:05:00Z)<<}` |
| Deleted text next to inserted text | `{~~old~>new~~}{>>Ana Lima (2026-09-29T14:05:00Z)<<}` |
| A comment on some text | `{==text==}{>>Ana Lima (2026-09-30T08:15:00Z): comment<<}` |
| A comment on a point | `{>>Ana Lima (2026-09-30T08:15:00Z): comment<<}` |
| An inserted or deleted paragraph break | `{++` or `{--` around the blank line between the paragraphs, then author and date |

Neighbouring changes by the same person at the same time are joined into one span. A substitution made by two authors names both — the deletion's author first. Changes inside a link's text or a bold/italic run stay inside it: `[the {++new ++}page](url)`. Formatting-only changes are not shown. A document with no tracked changes and no comments is written exactly as it would be without change tracking — nothing is escaped or altered.

### Accepting or rejecting all changes

The `--revisions` flag (MCP: `revisions`) controls how tracked changes appear in the output:

| `revisions` | What you get |
|---|---|
| `markup` (default) | Full CriticMarkup: every change, author, timestamp, and all comments |
| `accept` | The document as it reads after Accept All — no markup, no comments |
| `reject` | The document as it reads after Reject All — no markup, no comments |

`accept` and `reject` apply throughout: body, tables (inserted/deleted rows and cells are kept or dropped accordingly), text boxes, and footnotes.

## PowerPoint (.pptx)

Each slide becomes a Markdown section in deck order. anymd extracts the slide **title**, **bullet points**, **tables**, **chart data** (the underlying values, not the rendered chart), and **speaker notes**. Pictures are [exported as image files](#embedded-images). Use `--pages` to select specific slides.

## Spreadsheets (.xlsx, .xls, .ods, CSV, TSV)

anymd produces one Markdown table per sheet. Dates are written as ISO 8601 strings. Output is capped at 2,000 rows per sheet to prevent runaway responses from large workbooks.

Use `--pages` to select specific sheets by index or name — for example `--pages 1,3` to include only the first and third sheets.

## EPUB

Each chapter in the EPUB spine order becomes a Markdown section, prefixed with the book's title and author. Images are [exported as files](#embedded-images). Use `--pages` to select specific chapters.

## HTML and URLs

anymd fetches a URL or reads a local HTML file and returns the **main article content only**. Navigation menus, cookie banners, sidebars, and footers are dropped. Relative links are resolved against the base URL or file path. Code blocks preserve their language annotation. URL fetches are guarded against server-side request forgery; see the Security documentation for details.

## Markdown, text, JSON

Markdown, plain text, and JSON files are returned unchanged. Pagination and the token budget still apply — long files are windowed with `--pages`.

## Embedded images

Pictures inside DOCX, PPTX, EPUB, and PDF are exported automatically to a shared cache and referenced inline. This lets an agent open an extracted image directly, even though the source file is a binary container.

anymd writes each image to `<cache>/images/<first 16 hex of SHA-256>.<ext>`, where `<cache>` is `$ANYMD_CACHE_DIR`, or the platform default (`~/.cache/anymd`, `~/Library/Caches/anymd`, `%LOCALAPPDATA%\anymd\cache`). The same picture embedded in multiple documents is stored once. Files unused for 30 days are removed; the folder is kept under 2 GiB with the oldest files pruned first. This cleanup runs at most once a day, at CLI or server start. Images over 50 megapixels are refused.

The Markdown reference looks like this:

```markdown
![Figure 1: Quarterly revenue by region](/home/me/.cache/anymd/images/9f2c1a7be03d55a4.png)
<!-- image: 240x150, slide 3 -->
```

**Caption detection.** For DOCX and PPTX files, the `descr` alt-text attribute is used when present. For EPUB, the `alt` attribute on the `<img>` element. In a PDF, the nearest line directly above or below the image (within ~0.5 in) that begins with `Figure`, `Fig.`, `Table`, `圖`, `图`, or `表` followed by a number.

**Decorative images are skipped.** Images smaller than 48 × 48 px and any picture that appears on three or more pages, slides, or chapters (logos, running ornaments, repeated headers) are not exported.

**Which images are exported.** DOCX `word/media` folder contents, PPTX slide pictures in slide order, and EPUB `<img>` files. A reference costs only its two inline lines against the token budget — the image file itself is never counted.

**Known gaps in this version.** Figures drawn as vector graphics (charts and diagrams made of lines and text), inline images, CMYK rasters, JPEG 2000, JBIG2, CCITT, and images with soft-mask transparency are not currently exported.
